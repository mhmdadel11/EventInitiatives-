نظام إدارة المنشورات والمبادرات
التحويل إلى ASP.NET Core MVC + SQL Server

مبدأ التحويل:
- تم نسخ CSS الأصلي وJavaScript الأصلي كما هما دون تعديل.
- تم الاحتفاظ بعناصر HTML والنصوص والتسميات والتفاصيل المرئية الأصلية؛ التغيير في مراجع ملفات الخلفية فقط.
- تم استبدال طبقة Supabase (Auth / Database / Storage) بخدمات ASP.NET Core Identity وSQL Server وتخزين ملفات خاص خلف تسجيل الدخول.
- لم تتم إضافة صفحات أو تغيير خطوات العمل الموجودة في الواجهة الأصلية.

المتطلبات:
- .NET 8 SDK على جهاز التطوير أو السيرفر.
- SQL Server متاح للتطبيق.
- لا يحتاج الموظفون إلى Visual Studio أو .NET SDK أو SQL Server على أجهزتهم بعد النشر؛ يستخدمون المتصفح والرابط فقط.

إعداد قاعدة البيانات:
- الاتصال الافتراضي في appsettings.json:
  Server=MOHAMED_ADEL;Database=EventInitiatives_MVC_DB;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true
- غيّر Server فقط إذا كان اسم خادم SQL Server لديك مختلفًا.
- ينشئ التطبيق قاعدة البيانات والجداول عند أول تشغيل باستخدام EF Core EnsureCreated.
- يستخدم جداول ASP.NET Core Identity للمستخدمين والأدوار، وجدولي Events وEventMedia للبيانات والوسائط.
- هذه آلية إنشاء أولي لقاعدة جديدة. لا تخلط EnsureCreated مع EF Migrations على نفس قاعدة البيانات. قبل توسعة النظام الإنتاجية يُفضّل الانتقال إلى Migrations.

تشغيل المشروع:
1) فك ضغط الملف.
2) افتح EventInitiatives.Mvc.csproj في Visual Studio 2022 أو افتح المجلد في VS Code.
3) تأكد أن SQL Server يعمل وأن Connection String صحيح.
4) افتح PowerShell داخل مجلد المشروع واضبط حساب المدير الأول (مثال):
   $env:BootstrapAdmin__Email = "admin@example.com"
   $env:BootstrapAdmin__Password = "ضع-كلمة-مرور-قوية-هنا"
5) نفّذ:
   dotnet restore
   dotnet run
6) افتح رابط localhost الذي يظهر في نافذة التشغيل.
7) سجّل الدخول بالبريد وكلمة المرور اللذين ضبطتهما في الخطوة 4.

إضافة حسابات الموظفين:
- النسخة الأصلية كانت تعتمد على إنشاء حسابات الموظفين من لوحة Supabase Authentication ولم يكن بها نموذج تسجيل مستخدم جديد داخل الواجهة.
- في هذه النسخة تم الحفاظ على نفس سلوك تسجيل الدخول وعدم إضافة شاشة تسجيل جديدة.
- أُضيف مسار إداري خلفي لإنشاء حساب موظف بواسطة المدير فقط: POST /api/admin/users مع JSON يحتوي email وpassword، ويُرسل الطلب من جلسة المدير المسجّل دخوله.
- يمكن تنفيذ الطلب من Postman بعد تسجيل دخول المدير والحفاظ على Cookie الجلسة. لا تضع كلمات المرور في ملفات المشروع أو تشاركها.

الصور والفيديوهات:
- الحد الأقصى للصورة 20 MB وللفيديو 50 MB كما في الواجهة الأصلية.
- الأنواع: JPG/JPEG/PNG/WEBP/GIF وMP4/WEBM/MOV/M4V.
- الملفات تحفظ خارج wwwroot في App_Data/uploads، ولا يمكن فتحها إلا بعد تسجيل الدخول.
- يجب أن تكون App_Data/uploads على مساحة تخزين دائمة مع نسخ احتياطي عند النشر.

النشر لجميع الأجهزة:
- انشر تطبيق ASP.NET Core على سيرفر متاح للموظفين، واربطه بقاعدة SQL Server مركزية.
- استخدم HTTPS وشهادة TLS صالحة.
- احتفظ بمجلد App_Data/uploads ونسخه احتياطيًا.
- الموظفون يفتحون الرابط من المتصفح؛ لا يحتاجون إلى تثبيت برامج.

مراجعة ما قبل الإنتاج:
- هذه حزمة تحويل أولية؛ يجب إجراء dotnet build وتجربة تسجيل الدخول والإضافة والتعديل والحذف والتقويم والسحب والإفلات والرفع والتقارير على جهازك قبل النشر.
- راجع سياسات كلمات المرور والجلسات والنسخ الاحتياطي وصلاحيات حسابات الموظفين مع مسؤول تقنية المعلومات.


تحديث صفحة تسجيل الدخول (22-11-2026):

- عند فتح رابط النظام دون تسجيل الدخول، يحوّل ASP.NET Core المستخدم إلى /Account/Login.

- بعد نجاح الدخول يعود المستخدم إلى الصفحة التي طلبها أو إلى الصفحة الرئيسية.
- تسجيل الخروج من زر النظام يمسح جلسة Identity؛ وعند تحديث الصفحة يعود المستخدم إلى صفحة الدخول.
- لا يمكن التحقق من Build داخل بيئة إعداد الملف لعدم توفر .NET SDK هنا؛ نفّذ Rebuild Solution في Visual Studio بعد فك الضغط.
